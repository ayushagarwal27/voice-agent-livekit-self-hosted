# NOTES

Running log of decisions, surprises, and review-call talking points. One entry per phase.

## Phase 0 — Scaffold

- Built the full directory layout, `uv init` (Python 3.11), `.gitignore`, `.env.example`.
- Added deps via `uv add`: verified every `livekit-agents` extra (`deepgram`, `openai`, `groq`, `cartesia`, `silero`, `turn-detector`) actually exists on PyPI for the installed 1.8.8 release before adding, per rule 7 (don't trust names from memory).
- **Surprise:** `uv add` repeatedly stalled for 10+ minutes with almost no CPU time used and an empty `.venv`. Diagnosed it as a hung IPv6 connection (handshake completes, then no data ever arrives — a path-MTU blackhole, not a slow download). Killing the process and retrying worked immediately because the wheel cache (~13GB) was already warm from the earlier attempt. If `uv add`/`uv sync` ever appears to hang with low CPU usage, check for a stuck IPv6 connection (`lsof -p <pid> | grep TCP`) before assuming it's just a big download.
- Decided to keep LiveKit's API key/secret **out of** `livekit/livekit.yaml` entirely (confirmed via the server's Go source that it reads a `LIVEKIT_KEYS` env var as a fallback) so the committed yaml has no secret in it — keys are injected at container start from `.env` via `docker-compose.yml`. This satisfies rule 6 (no secrets in git) without diverging from the repo layout in AGENTS.md.
- Installed the `lk` CLI via Homebrew for manual two-tab audio testing in Phase 1.

## Phase 2 — Voice agent, hard-coded config

- `agent/worker.py`: `AgentSession` with Silero VAD (loaded once in `prewarm`), Deepgram STT, OpenAI LLM (chose OpenAI over Groq since only `OPENAI_API_KEY` is set in `.env`), Cartesia TTS, and the local English turn-detector model. Persona is a hard-coded `PERSONA` constant per rule 5 — Phase 4 must delete it.
- Greeting uses `session.say(GREETING)` (fixed text, not LLM-generated) in `Agent.on_enter`, so the mandatory "this call is being recorded" line is always said verbatim — this also makes Phase 9's deterministic compliance regex reliable instead of hoping the LLM phrases it the same way every time.
- Verified the installed API against source, not memory (rule 7): `AgentSession`/`Agent` in 1.8.8 take `stt`/`llm`/`tts`/`vad` directly and a `turn_handling` dict (the old separate `turn_detection=` kwarg still works but is deprecated).
- **Surprise:** the SDK's default interruption mode ("adaptive") calls LiveKit's own cloud inference gateway (`agent-gateway.livekit.cloud`) and fails with 401 since we have no LiveKit Cloud account — which would silently violate rule 2 (self-hosted only) if left on its default. Fixed by setting `turn_handling={"interruption": {"mode": "vad"}}`, which keeps interruption detection fully local (VAD-based). Same reasoning led to *not* switching to the newer `livekit.agents.inference.TurnDetector` (it also defaults to a cloud call with local fallback) and instead keeping the "deprecated" but fully local `livekit.plugins.turn_detector.english.EnglishModel`.
- Model files (Silero VAD, turn-detector ONNX) are fetched once via `uv run -m livekit.agents download-files` into the HF cache outside the repo — confirmed nothing leaked into `git status`.
- Verified automatically: `console` mode boots, connects to Deepgram (STT) and Cartesia (TTS), and speaks the exact greeting (seen in `conversation_item_added` logs) with no cloud calls. `dev` mode registers cleanly with our self-hosted server (`"url": "ws://localhost:7880"`) and shuts down cleanly.
- **Still needs the owner:** an actual spoken back-and-forth (console mode needs a real terminal/mic — the automated run here used `/dev/null` for stdin, which can't drive the console's push-to-talk keystroke reader; and dev mode needs a tab/`lk` join to actually talk to the agent).
- **Surprise (owner's manual test):** `lk room join --identity X --open meet <room>` creates *two* room participants, not one — a headless Go-SDK connection named exactly `X` (publishes no audio) plus a separate browser tab named `X_observer` (the real mic). `RoomIO` links to "the first participant that joined" by default, which was the headless one, so the agent was deaf to the actual browser mic even though everything else looked healthy. Fix: use `lk token create --room <room> --identity X --join --open meet` instead — it only prints a token and opens the browser, no shadow participant. Keep this in mind for any future manual room testing (not just Phase 2); `lk room join` is fine for file/demo-video publishing per its own docs, just not for "a human talks over a browser mic" tests.
- Phase 2 gate confirmed by the owner: real two-turn conversation over the browser tab's mic. "Hi." -> greeting + "Hello! Thanks for calling Acme Telecom. How can I help you today?"; "What's the weather today?" -> agent correctly declined (no hallucinated answer) and steered back to Acme Telecom support, staying in persona. Logs show the full STT-final -> LLM -> TTS chain for each turn, and a clean session close on participant disconnect.

## Phase 3 — Agents API + storage

- `storage/models.py`: one `Agent` table (`id`, `name`, `system_prompt`, `voice`, `model`, `created_at`) via SQLAlchemy 2.x's `DeclarativeBase`/`Mapped`/`mapped_column` style (verified against the installed 2.1.5, not memory, per rule 7). `storage/db.py` creates the engine from `DATABASE_URL` (falls back to `sqlite:///./dev.db`), enables SQLite WAL mode, and exposes `init_db()` + a `get_session()` FastAPI dependency.
- `backend/main.py` + `backend/routers/agents.py`: `POST /agents` (201, Pydantic `Field(min_length=1)` on every field so blanks 422 automatically) and `GET /agents/{id}` (404 on unknown id via `session.get`).
- `scripts/seed_agent.py` inserts the Acme Telecom persona (idempotent — checks for an existing row by name first).
- `tests/test_agents_api.py`: FastAPI `TestClient` against an in-memory SQLite DB (via `dependency_overrides` on `get_session`, `StaticPool` to keep one shared connection alive). Covers create+fetch, 404, and 422 for every missing/blank required field (10 tests).
- **Surprise:** `app.on_event("startup")` is deprecated in FastAPI 0.147 (checked via a live `DeprecationWarning`, not assumption) — used the `lifespan` context-manager form instead.
- **Surprise:** `storage/db.py` didn't call `load_dotenv()`, so `backend/main.py` silently ignored the `.env`'s `DATABASE_URL` and would have written to a different default filename than intended. Fixed by loading `.env` in `storage/db.py` itself (same pattern as `agent/worker.py`) and matching the default to `.env.example`'s `sqlite:///./dev.db`.
- **Surprise:** running a script as `uv run python scripts/seed_agent.py` (bare path) put `scripts/` itself on `sys.path`, not the repo root, so `storage` wasn't importable. Fixed by invoking it as a module instead: `uv run python -m scripts.seed_agent`. Added `[tool.pytest.ini_options] pythonpath = ["."]` to `pyproject.toml` for the same underlying reason (tests importing `backend`/`storage`).
- Verified automatically: `uv run pytest -q` (10 passed), plus the exact `curl` sequence from AGENTS.md's Phase 3 "Test it" against a real `uv run uvicorn backend.main:app` process — create (201), fetch (200, matches), unknown id (404), missing field (422) — confirmed via the uvicorn access log, not just curl's own exit status.
